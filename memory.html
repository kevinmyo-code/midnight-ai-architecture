Midnight AI · Memory System

How context is filed and recalled

A solo developer and a crew of agents work across hundreds of sessions, but no session can hold the whole project in its prompt. So memory is pull-based: a thin dashboard is always loaded, the rules are locked, and everything else lives in a curated library that a cheap librarian agent files into and reads back on demand — never bulk-loaded on the chance it might be needed.

The read order

Every session orients the same way, cheapest and most-current first. Only the first two tiers are ever loaded up front; the third is fetched a slice at a time.

1

The dashboard memory/MEMORY.md

A thin, always-loaded status board kept under 80 lines: the active sprint, one-line blockers, what is in flight, and notes for the next session. It answers "where are we right now" without opening anything else. State lives here; when state and the rules disagree, the dashboard wins for state.

2

The rules CLAUDE.md

Locked architecture, frozen decisions, and guardrails. It changes rarely and wins ties on rules. This is the constitution the crew works under: pull-based tools only, additive database migrations, frozen-list decisions that persona reports cannot reopen.

3

The library memory/library/

The deep archive. Never bulk-read into a session; instead the librarian is dispatched to retrieve just the relevant digest. A card catalog (INDEX.md) lists every shelf in one line each, so the librarian knows where to look before opening anything.

The library shelves

One file per kind of long-term knowledge. Each shelf is a narrative, not a dump — enough for a future session to judge relevance from the catalog line, then open only what it needs.

decisions.md

Frozen-list deltas and strategy re-evaluations: pricing, integrations, product direction.

blocking.md

Blocker root-cause narratives and fix status, tracked by id across sessions.

sprints.md

Sprint status snapshots and the verification-drive checklist.

hardware.md

The device validation ledger: what is proven on the real head unit and what still is not.

backlog-*.md

Domain backlogs — cruise, music, nav, OBD, voice, visuals, recaps — parked ideas with context.

playbook-*.md

Per-agent accumulated craft: codebase conventions and gotchas an agent compounds over time.

lessons.md

The failure-mode ledger: mistakes the crew has made and the rule that now prevents each.

archive.md

Closed or superseded items and the historical session log.

INDEX.md

The card catalog — one line per shelf. If a file is not listed here, it does not exist.

The librarian

A dedicated agent on the cheapest model owns the library, in two modes. The orchestrator dispatches it instead of pulling shelves into the main context — one small digest costs far less than reading a whole shelf into an expensive session.

Retrieve

Answer, then cite

Given a question, the librarian reads the catalog, opens only the relevant shelves, and returns a curated digest with citations back to the files — so the main session gets the answer, not the raw archive.

Runs instead of the orchestrator reading shelves directly.

File

Sort, then index

At session end the orchestrator hands over the raw session notes; the librarian sorts each fact onto the right shelf, updates the dashboard, and bumps the catalog. Filing is batched into one dispatch, not drip-fed.

Keeps the archive curated rather than append-only.

How it compounds

Knowledge does not evaporate at the end of a session. Two write-back loops turn each session's learning into something the next spawn reads — the only way agents "learn" without any model training.

Capture

Agents emit durable facts as tagged lines; the orchestrator collects them.

Next time
Recall on demand
A future session retrieves just the relevant digest and builds on it.

The lessons loop. When a claim turns out wrong, it becomes an entry in lessons.md — what was claimed, what was actually true, and the rule that would have caught it. That rule then graduates into the relevant agent's own instructions, so the same class of mistake cannot silently return. Memory here is not just facts; it is the crew getting harder to fool.

Why pull-based

The same principle runs through the whole product: context is fetched when needed, never pre-injected on speculation. It keeps every session cheap and current, it stops stale facts from silently steering the work, and it means the archive can grow without end because no session ever pays to load the parts it does not touch. Grounding memory in real, checkable records — car telemetry, committed decisions, citations back to a file — is also what keeps it trustworthy rather than a drifting story the system tells itself.
